=== Shape concerns

* Seven spokes in ten minutes is ~80 s each, before the intro. The hub makes skipping cheap;
  merging (1+2, 3+5) is still an option.
* "It's all about the infrastructure" is the thesis, not a peer section -- it may work better as
  the turn the earlier sections build to.

== Format and look

* slidedown, `terminal` theme. Each command + its output is a terminal window (`.term` in
  `talk.sd`); console syntax highlighting on typewriter prompts.
* Needs slidedown `main` at or after FNNDSC/slidedown#1 (merged 2026-10-16): deck CSS beats
  theme, console highlighting, `tw-done`, nexus cursor box, returns keep typed menus.
* Build: `uv run --project ~/src/slidedown slidedown . talk --inputFile talk.sd --theme terminal`.
* Terminal behaviour: the cursor sits at the end of the command while it types, then follows the
  last printed line as bullets reveal. On the hub, the menu prints line by line once
  `talk --outline` finishes, and the cursor parks blinking under it. Up/Down boxes the current
  entry. Relies on slidedown's `tw-done` class (set when a typewriter finishes).
* No blank lines inside slide bodies -- slidedown turns them into `<br>`.
* Deck order: title, whoami, whatido, hub (`.id{outline}`), then the spokes, two slides each
  (conclusions one). `transition: zoom` is on: the chosen hub entry flies up to become the
  spoke's heading, so each spoke's first `.h1` must match its menu text.
* Spoke content is a *draft*. 1, 2, 5 (part), 6 are adapted from the Red Hat deck; 3, 4, 7 are
  placeholders written without Rudolph's input -- expect them to be replaced.
